
❯ 例えばアニメーション中に、ポップアップ、サブサーフェスが開くときのアプリへの画面領域、クリ 
  ップ範囲の通知などはどうなるのでしょう                                                     

● これは直接移動方式の重大な問題点です。

  発生する問題

  1. wl_surface.enter / leave イベント

  ワークスペースツリーをスライドさせると、wlrootsはサーフェスがoutputの範囲外に出た瞬間に自動
  でleaveを送信します。

  FROM workspace がスライドアウト中:
    → 各surfaceにwl_surface.leave(output)
    → クライアントはHiDPI scaleをリセット
    → frame callbackが停止 → 動画・アニメーションが止まる
    → GTKなどはウィンドウを再描画

  TO workspace がスライドイン中:
    → 各surfaceにwl_surface.enter(output)
    → 同様に再描画トリガーの可能性

  2. ポップアップ・サブサーフェスの配置

  アニメーション中にポップアップが開くと、xdg_positionerはサーフェスのsceneでの実際の座標を使
  って配置を計算します。ワークスペースツリーがまだx=+1920にあれば、ポップアップは画面外に配置
  される可能性があります。

  3. 入力領域

  両ワークスペースがenabled=trueの状態では、カーソルイベントがFROMワークスペースのウィンドウ
  にも届きます。スライド途中で誤クリックが発生し得ます。

  4. wlr_surface configure との不整合

  xdg_toplevel.configureで通知したgeometryとscene上の実際の位置が一時的にズレるため、クライア
  ントによっては描画の乱れが起きます。

  まとめ

  ┌──────────────────────┬──────────────────────────┬────────────────────┐
  │         問題         │   スナップショット方式   │    直接移動方式    │
  ├──────────────────────┼──────────────────────────┼────────────────────┤
  │ enter/leave イベント │ 発生しない               │ 発生する           │
  ├──────────────────────┼──────────────────────────┼────────────────────┤
  │ frame callback       │ 影響なし                 │ off-screenで停止   │
  ├──────────────────────┼──────────────────────────┼────────────────────┤
  │ ポップアップ配置     │ 正常                     │ 画面外になる可能性 │
  ├──────────────────────┼──────────────────────────┼────────────────────┤
  │ 入力の誤ヒット       │ なし                     │ 対策が必要         │
  ├──────────────────────┼──────────────────────────┼────────────────────┤
  │ 動画・アニメーション │ 静止（スナップショット） │ 停止する可能性     │
  └──────────────────────┴──────────────────────────┴────────────────────┘

  直接移動方式でこれらを正しく対処しようとすると、入力ブロック・configure送信の抑制・ポップア
  ップの特別扱い…と複雑になり、結果としてスナップショット方式の方がシンプルで正確です。現在の
  実装を維持する方が良いと思います。
